Harness Engineering of Claude Code

使用者對這套「代理人鷹架」，到底能動到多深？——從一句過度簡化的答案，到修正後的完整分層。

01 — 定義

什麼是 Harness？

Harness（鷹架）是通用術語，指包在一顆語言模型外面的整套鷹架——工具、prompt、context 管理、執行環境——把一個模型變成能完成任務的 agent。這不是 Claude Code 專屬的說法，但 Claude Code 官方文件明確認領了它。

“Claude Code serves as the agentic harness around Claude: it provides the tools, context management, and execution environment that turn a language model into a capable coding agent.”

— Claude Code 官方文件

02 — 分層

核心、鷹架、控制層

三層由內而外：模型本身、Claude Code 提供的執行鷹架、以及使用者能配置的一切。使用者的規範不是站在鷹架外面，而是直接作用在最外圈——甚至能穿透進中間層。

控制層 — 使用者可配置
CLAUDE.md · Skills · settings.json · Hooks · Subagents · MCP · Agent SDK
鷹架 — Claude Code CLI
工具呼叫、context 管理、執行環境、agentic loop Anthropic 提供的現成鷹架本體
核心
語言模型（Claude）

03 — 修正

對話中的一次自我修正

修正前使用者只能給 Claude Code 外部規範。

修正後使用者能在多個層級上，直接工程化這套鷹架的行為。

這個修正本身，就發生在這場對話的追問裡——「我們給的規範不能算是 harness engineering 嗎？」

04 — 機制

控制機制對照

把「軟規則」與「硬程式碼」分開看，才看得出使用者實際能動的深度。

機制 性質 說明
CLAUDE.md 軟規則 自然語言指示，依賴模型理解遵循，不強制執行
Skills 軟規則 依需求載入的程序指引，同樣不強制
settings.json 權限 硬程式碼 每次工具呼叫都檢查，deny 規則強制擋下
環境變數 硬程式碼 直接注入 session 執行環境
Hooks 硬程式碼 shell / HTTP 攔截生命週期事件，能阻擋或改寫工具呼叫
Subagents 硬程式碼 強制限制工具集、指定 model、獨立 system prompt
MCP servers 硬程式碼 新增真正的工具能力，非建議
Agent SDK 硬程式碼 完全自建 loop、工具、context 管理——跳出 Claude Code 本體

05 — 結論

CLAUDE.md 是軟規則；但 hooks、permissions、MCP、Agent SDK 都是真正在執行的程式碼。Harness engineering 不是外部建議，而是對這套鷹架由淺到深的工程。
