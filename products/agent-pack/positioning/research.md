# Agent Pack 產品定位

**Kick off 討論稿｜三個候選方向，尚未選定定位**

先對齊「為誰解決什麼問題」，再決定功能與技術。

目前的出發點是：研究一套可以安裝在單機上的簡易 Agent 管理系統，與 AIDMS 的多 GPU node 管理範圍區分。「單機、簡易」描述了產品形式，還需要說清楚誰會因為什麼需求，願意安裝、使用或購買。

## 三個定位方向

| 候選方向 | 主要使用者 | 使用者想完成的事 | 產品核心價值 |
|---|---|---|---|
| **個人 AI 助理工作站** | 專業工作者、研究人員 | 整理資料、研究、產出文件、執行例行任務 | 買回來就能用自己的 AI 助理 |
| **企業部門的 AI Agent 套件** | 中小企業、部門主管及 IT | 在內部導入 Agent，協助團隊處理工作 | 容易部署、資料可控、有人維護 |
| **Agent 部署與管理工具** | 工程師、系統整合商 | 快速安裝、設定與維護不同 Agent | 減少部署與維運時間 |

這三個方向是待討論的產品假設，不代表市場需求已驗證，也不代表目前軟體已具備上述能力。

## 方向一：個人 AI 助理工作站

**讓使用者直接透過 AI 助理完成工作。**

- 主要使用者：專業工作者與研究人員。
- 核心工作：整理資料、進行研究、產出文件，以及執行例行任務。
- 產品重點：容易開始使用、任務成果有用、日常體驗順暢。
- Kick off 要釐清：第一位使用者是誰？他每天最需要助理協助的三件事是什麼？

候選定位句：為專業工作者提供可在單機使用的 AI 助理工作站，協助完成研究、資料整理與文件產出。

## 方向二：企業部門的 AI Agent 套件

**讓企業部門更容易導入並持續使用 Agent。**

- 主要使用者：中小企業、部門主管與負責導入的 IT。
- 核心工作：在內部建立 Agent 使用環境，協助團隊處理工作。
- 產品重點：導入便利、資料使用範圍可控，以及後續維護服務。
- Kick off 要釐清：誰付錢、誰使用、誰管理？先落在哪一個部門工作情境？

候選定位句：為中小企業與企業部門提供可安裝在單機上的 AI Agent 套件，降低導入與維護門檻，協助團隊處理日常工作。

「資料可控」的具體承諾仍需定義；單機安裝不自動代表所有資料都留在本機。

## 方向三：Agent 部署與管理工具

**讓工程師更容易把 Agent 安裝好、維護好，再交給別人使用。**

- 主要使用者：工程師與系統整合商。
- 核心工作：快速安裝、設定與維護不同 Agent。
- 產品重點：技術彈性、整合效率，以及部署維運所需的時間。
- Kick off 要釐清：要支援哪些 Agent？目標客戶目前最耗時的導入與維護步驟是什麼？

候選定位句：為工程師與系統整合商提供單機 Agent 部署與管理工具，縮短安裝、設定及日常維護時間。

## 初步討論建議

以目前「單機、簡易、與 AIDMS 區分」的出發點，可先把 **企業部門的 AI Agent 套件** 作為會議討論的定位假設。

這個方向可以連結硬體交付、企業導入與後續服務，但仍須確認第一批客戶是否真的是企業部門。此處是討論建議，**尚未核定採用第二個方向**。

首先要回答的分岔是：讓一般使用者直接使用 AI 助理，還是讓企業 IT／工程師更容易把 Agent 導入給別人使用？

## Kick off 先決定四件事

| 要決定的事 | 會議問題 | 希望產出的答案 |
|---|---|---|
| 第一批客戶 | 誰使用、誰付錢、誰負責管理？ | 一個明確的客戶群與角色分工 |
| 第一個要解決的工作 | 哪一至三個具體工作最需要改善？ | 可描述、可展示成果的使用情境 |
| 為什麼需要單機設備 | 是資料留在內部、持續執行任務、成本，還是隨硬體交付的便利性？ | 客戶選擇單機方案的主要理由 |
| 客戶買到什麼 | 軟體、預裝工作站，還是包含安裝與維護的完整方案？ | 交付形式與服務範圍 |

## 會議共識：用一句話寫下定位

> 我們為【第一批目標客戶】，提供可安裝在單機上的【產品類別】，讓他們能夠【完成最重要的工作】，並以【主要價值】作為選擇我們的理由。

會後應有一個優先定位、一至三個核心情境，以及仍需訪談或驗證的假設。功能清單與技術選型接著依這個定位展開。
